# 대규모 증분 갱신 후속 실험 과제

상태: **미실행 · 리소스 확보 후 재개**  
관련 결과: [공개 임베딩을 이용한 로컬 실험 기술보고서](technical-report.md)

## 배경과 질문

로컬 실험은 기존 1만 벡터에 신규 1만 벡터를 삽입한 조건에서, 증분 인덱스와 같은 최종 데이터로 재구축한 인덱스의 재현율 차이를 측정했다. 이 결과만으로 수백만 개 이상의 벡터, 장기간 반복 갱신 또는 분포가 크게 달라진 신규 데이터에 대한 동작을 판단할 수 없다.

리소스가 확보되면 pgvector와 Qdrant를 대상으로 다음을 확인한다.

1. 규모가 커질 때, 같은 최종 데이터의 증분 인덱스와 재구축 인덱스 사이에 Recall 차이가 생기는가?
2. 신규 집합의 상대적 크기, 기존 집합과의 거리·분포, 군집 구조와 삽입 순서가 그 차이에 어떤 영향을 주는가?
3. 동일한 신규 벡터를 한 번에 삽입할 때와 여러 논리적 배치로 나누어 삽입할 때 어떤 차이가 생기는가?
4. 삭제만 수행할 때, 삭제와 신규 삽입을 반복할 때, 기존 ID의 벡터를 교체할 때 품질과 유지 비용이 어떻게 변하는가?
5. 기본 실험 이후 필터, 선택도, 메타데이터 카디널리티를 바꾸면 결과가 어떻게 달라지는가?

## 재개 시 실험 설계에 반영할 사항

- 공개된 실제 임베딩을 사용하고 데이터의 출처, 표본, 거리 함수와 신규 집합의 분포를 기록한다. 구체적인 데이터셋과 크기는 확보한 CPU·메모리·디스크·시간·예산에 맞춰 정한다.
- 같은 최종 벡터 집합을 사용하는 증분 구축과 fresh 재구축을 비교하고, 각 체크포인트의 실제 데이터에 대한 정확 최근접 이웃으로 Recall@k를 계산한다. 중간 상태의 데이터가 다르면 각 상태의 fresh 기준으로 비교한다.
- 삽입 전용, 삭제 전용, 삭제·삽입 반복, 같은 ID 교체는 서로 다른 워크로드로 기록한다. 전체 갱신량과 최종 데이터를 고정한 배치 분할 비교를 포함한다.
- 구축 및 검색 설정을 각 DB에서 별도 보정하고, 검색 재현율과 지연시간·처리량·쓰기 및 재구축 비용을 함께 측정한다. 데이터 규모, 반복 횟수, 신규 비율, 질의 수와 판정 기준은 재개할 때 명시한다.
- PostgreSQL은 초기 대량 적재에 COPY를 사용하고, 검색 세션에서 `enable_seqscan=off`를 설정한 뒤 실제 HNSW 실행 계획을 확인한다. Qdrant는 적재 후 인덱싱 상태와 HNSW 검색 경로를 확인한다.
- 공정한 비교를 위해 클라우드 인스턴스에서 독립적으로 실행한다. 실행 환경, 데이터 전송, 스토리지 및 인스턴스 비용을 사전 산정하고 스모크 실측으로 전체 실행 시간과 비용을 갱신한다. 실제 규모와 비용 상한은 아직 정하지 않았다.
- 스모크, 본 실험, 결과 분석을 구분하고 각 단계의 완료 기준을 실행 전에 확정한다. 기존 실험의 12시간 목표를 새 실험의 승인된 상한으로 취급하지 않는다.

## 참고할 선행 자료

- [Azure Cosmos DB / DiskANN 논문](https://www.vldb.org/pvldb/vol18/p5166-upreti.pdf): 1,000만 벡터 데이터의 군집별 삽입·삭제와 삭제 시 연결 복구 정책을 평가했다. 삽입 전용 실험은 아니다.
- [IP-DiskANN](https://arxiv.org/abs/2502.13826): 1,000만·3,000만 벡터 데이터의 스트리밍 갱신 및 일부 시점의 재구축 대조를 평가했다. DB 제품 비교가 아니라 알고리즘 비교다.
- [Intel SVS Dynamic Indexing Benchmark](https://intel.github.io/ScalableVectorSearch/benchs/dynamic.html): 100만~1억 벡터 데이터에서 일정 크기를 유지하며 무작위 삭제·삽입을 반복했다.
- [HAKES](https://vldb.org/pvldb/vol18/p3049-ooi.pdf): 초기 100만 벡터에 20만 벡터씩 네 차례 추가하고 분포 이동을 평가했다. 학습형 인덱스의 실험이다.
- [VectorDBBench](https://zilliz.com/vdbbench-leaderboard?database=ZillizCloud%2CMilvus%2CPgVector%2CElasticCloud%2CPinecone%2CQdrantCloud%2CWeaviateCloud&dataset=medium&filter=none%2Clow%2Chigh): 1,000만 벡터 지속 적재 중 제품 성능을 비교한다. 같은 최종 데이터의 증분·fresh 재현율 차이를 분리한 자료로 취급하지 않는다.

## 재개에 필요한 준비

인스턴스와 예산이 확보되면 데이터 크기, 실험 조합, 동시 실행 정책, 비용 및 시간을 산정하고 실행 계획을 구체화한다. 기존 로컬 실험의 데이터와 전체 저장소 백업은 `/Volumes/JS2026/archive/incremental_vector_upsert/20261028-105659/repository`에 있다. 원본 데이터 일부는 공간 확보를 위해 로컬에서 제거됐으므로 재사용 시 외장 백업에서 복원하거나 출처에서 다시 받아야 한다.
